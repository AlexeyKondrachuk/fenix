# Деплой «Феникса» на VPS

На сервере понадобятся Docker Engine с Compose и открытый порт 80. Временная конфигурация Nginx открывает сайт по HTTP на IP сервера. Next.js и PostgreSQL доступны внутри сети Compose. Когда будет готов домен, настройте HTTPS перед использованием админки через интернет.

## Образ из GitHub Actions

Workflow **Fenix VPS** на каждый пуш в `main` собирает образ для `linux/amd64` и публикует его в GHCR. В сводке запуска указан адрес с digest, например `ghcr.io/alexeykondrachuk/fenix@sha256:…`. Если используете карты Яндекса, задайте `NEXT_PUBLIC_YMAPS_API_KEY` в переменных репозитория GitHub Actions до сборки.

На VPS клонируйте репозиторий в `~/fenix`. Для закрытого образа выполните `sudo docker login ghcr.io --username ИМЯ_НА_GITHUB` и введите токен с правом `read:packages`, которому доступен пакет. Если Docker вызывается без `sudo`, войдите в реестр под тем же пользователем, который будет выполнять деплой.

## Первый запуск и перенос

1. Скопируйте `deploy/production.env.example` в `.env.production`, ограничьте доступ к файлу командой `chmod 600 .env.production` и заполните значения. Один и тот же случайный пароль PostgreSQL укажите в обоих полях, например из `openssl rand -hex 32`. Секрет сессии и пароль админки задайте отдельно. Ключ карт подставляется при сборке образа.
2. Создайте `deploy-data/media` и задайте `SITE_URL=http://IP_СЕРВЕРА` в `.env.production`. Для перехода на HTTPS понадобятся домен, TLS-сертификат, порт 443 и обновлённая конфигурация Nginx. После перехода задайте публичный HTTPS-адрес в `SITE_URL`.
3. Для переноса скачайте в старой админке **оба** архива: базу и фото/видео. На время создания пары копий приостановите обновление контента. Передайте архивы на VPS по SSH и выполните команды ниже из каталога проекта. Для установки с пустой базой пропустите восстановление базы и распаковку медиа.

```sh
umask 077
printf 'FENIX_IMAGE=%s\n' 'ВСТАВЬТЕ_АДРЕС_С_DIGEST_ИЗ_ACTIONS' > deploy-data/image.env
dc() { sudo docker compose --env-file .env.production --env-file deploy-data/image.env -f compose.prod.yaml "$@"; }

dc up -d --wait postgres
dc pull app

# Только для переноса со старой установки, до первого запуска сайта.
# Восстанавливайте в пустую БД; транзакция откатится при ошибке.
dc run --rm -T app \
  sh -c 'pg_restore -d "$DATABASE_URL" --no-owner --no-privileges --single-transaction' < /path/to/fenix.dump
tar -xzf /path/to/fenix-media.tar.gz -C deploy-data/media

# Пользователь node в контейнере имеет UID 1000.
sudo chown -R 1000:1000 deploy-data/media
sudo chmod -R u+rwX,go+rX deploy-data/media

dc run --rm -T app node scripts/export-review-media.cjs
dc run --rm -T app npx --no-install prisma migrate deploy
dc run --rm --no-deps -T nginx nginx -t
dc up -d --wait
```

После запуска проверьте главную, обложки статей и перемотку видео. Для существующего видео выполните `curl -sS -D - -o /dev/null -H 'Range: bytes=0-1023' URL` и проверьте ответ `206 Partial Content`. Для проверки входа в админку используйте HTTPS или SSH-туннель.

Nginx читает медиа с диска через внутренний маршрут после проверки публикации или сессии в Next.js. Том подключён к Nginx только для чтения. Фото и видео статей и отзывов отдаются через `sendfile`. Прямой запрос к внутреннему маршруту возвращает 404. Изменение статуса публикации учитывается при каждом новом запросе.

При обновлении установки, где вложения отзывов ещё находятся в PostgreSQL, сначала сохраните дамп базы и остановите старый контейнер `app` командой `dc stop app`. После загрузки нового образа выполните экспорт, миграцию и запуск в порядке из примера выше. Экспорт переносит файлы в `deploy-data/media/review-media`, проверяет совпадение байтов и очищает поле в базе. Если экспорт завершился ошибкой, устраните её и повторите экспорт перед запуском миграции.

## Обновления через GitHub Actions

После первого запуска настройте окружение `production` в GitHub.

- Переменные `VPS_HOST` и `VPS_USER` задают адрес и пользователя, который владеет клоном `~/fenix`. На VPS этому пользователю нужен доступ к `git fetch origin main`, чтению GHCR и запуску Docker без запроса пароля. Членство в группе `docker` даёт права уровня root, поэтому доступ к деплою следует выдавать только доверенным администраторам.
- Секрет `VPS_SSH_KEY` содержит отдельный ключ для CI/CD, публичная часть которого установлена у пользователя деплоя. Секрет `VPS_KNOWN_HOSTS` содержит строку с ключом хоста, сверенным с отпечатком на VPS. SSH проверяет ключ хоста при подключении.

После пуша в `main` деплой запускается автоматически, если сборка прошла успешно. Для ручного запуска откройте **Actions → Fenix VPS → Run workflow**, выберите `main` и оставьте `deploy` включённым. Снимите галочку, если нужна только сборка. Workflow загружает выбранный коммит на VPS, проверяет конфигурацию Nginx, применяет миграции, ждёт готовности приложения и переустанавливает контейнер Nginx с текущей конфигурацией. Дамп и медиаархив используются только при первом переносе. После успешного обновления новый digest записывается в `deploy-data/image.env`.

Храните дамп PostgreSQL и архив медиа вне VPS. Том PostgreSQL и каталог медиа переживают пересоздание контейнеров.
